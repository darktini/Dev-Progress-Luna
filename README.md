# Dev Progress Luna

一套轻量、项目无关的开发工作流 skill。它以明确的需求、责任边界、风险相称的验证和可恢复交付组织开发；简单请求可以直接执行，复杂需求再进入正式的规划、实施、审核与集成流程。角色可以由同一 agent 分阶段承担，也可以在风险或项目要求需要时委派给独立 agent。

## 安装与入口

将 `skills/` 下的五个技能目录整体复制到宿主支持的技能发现目录，保持同级关系，例如工程的 `.agents/skills/` 或 `.codex/skills/`。宿主是否即时发现由宿主决定；文件落地不代表已激活。不要同时安装同名副本。

- `dev-progress-init`：初始化或更新项目印象及工程配置。
- `dev-progress-secretary`：分流轻量请求，或澄清、确认、归档和传达正式需求。
- `dev-progress-supervisor`：制定方案，按风险选择直接执行或委派，负责审核和集成。
- `dev-progress-worker`：在指定位置完成一个任务并进行风险相称的验证，交付候选成果。
- `dev-progress-shared`：公共契约，不是执行角色。

通常从初始化或秘书开始。目标明确、范围小、已获授权且容易核对的操作可走轻量直执行，不建立正式需求档案；复杂需求或已有确认需求进入 supervisor。角色表示责任边界，不要求为每个角色或任务创建独立 agent。自审必须如实说明，不能冒充独立审核。

## 工程产物

默认保存在工程 `docs/dev-workflow/`，初始化时可以选择其他工程内路径。每次需求使用独立、稳定的 `REQ-日期-短标识`，恢复任务不换 ID。

```text
docs/dev-workflow/
  PROJECT.md
  config.yaml
  INDEX.md
  secretary/<request-id>/REQUEST.md
  changes/<request-id>/DEVPROGRESS.md
  changes/<request-id>/evidence/       按需创建
```

项目印象、需求、任务状态各有唯一归属。历史原地保留；索引只导航。技能升级不覆盖工程档案。

## 能力与限制

普通任务可由当前 agent 在已核对的工作区实施并自审；风险、项目要求或用户指示需要时，再使用独立 worker、分支、worktree 或文件副本。委派与并行必须具备明确的基线、写入边界和资源独立性。实际文件修改与 agent 派发依赖宿主能力，本包不包含后台调度器。

验证范围由改动风险和影响决定：优先确认当前功能与直接关联回归，只在跨系统联调、重要里程碑、发布或存在广泛影响时进行全量检查。未变部分可以引用仍适用的既有证据；退出码成功不能掩盖脚本错误、中断或漏跑步骤。长期回归、阶段验证和临时诊断分别管理，普通尝试优先通过 Git 或可核对差异保留最少充分证据。

清理只处理授权范围内且归属明确的临时产物、测试和工作区。遇到权限、锁定、占用或工具限制时保留现场并报告，不强制删除、不提权或绕过阻碍；可选清理失败不应阻止功能交付。

默认不 push、不部署、不自动启用高级记忆。远端操作沿用用户授权及项目约定。高级扩展边界见 [扩展协议](skills/dev-progress-shared/references/extensions.md)。

本包的模板是输出资产，不是实际项目事实。初始化只生成有依据的内容；占位值不能作为确认或验收证据。
