# 执行与集成

## 隔离和串并行

默认一次执行一份需求。其他需求可以等待；若启用跨需求并行，必须额外明确共享资源与集成分支的单一所有者，不能各自假设独占。

普通任务由当前agent执行时，可使用已核对的当前工作区，以Git差异或必要恢复副本保留基线，不默认新建隔离集成分支、worker分支或整份工程副本；自审必须如实说明。用户或项目要求隔离/独立审核时仍遵守。

委派实现时保持候选成果与集成目标分离，按风险与工具选择独立worktree、分支或文件副本。根据工程已有约定命名，不硬编码主分支名称。派发前记录基线、目标和归属；保留用户未提交改动，不自动stash、清除或混入提交。

并行必须同时具备宿主 agent 能力、独立执行位置和资源独立性；允许的并发数来自配置及宿主限制。分析读/写集合和产出依赖，包括公共契约、配置、生成物、数据库、端口和测试服务。只读同一资源通常可并行；写入相互影响、读取对方待产出结果、独占外部资源或无法证明独立时串行。

无Git的委派任务使用必要隔离副本和可核对差异，默认串行；核对目标未变化后再接纳。不能建立必要隔离时，说明限制；已有授权允许当前agent直接执行且不要求独立审核时可改为直接执行，否则保留待处理，不能把正式工作区直接修改说成先审后合。

## 集成

1. 独立worker返回ready_for_review后确认已停止写入，再核对候选版本、实际差异、工作区状态与审核结论；同一agent直接执行时切回supervisor审核当前差异，不虚构独立交接。
2. 检查集成目标是否仍符合原基线/已知前移。使用项目约定的 merge、cherry-pick 或补丁接纳；不规定唯一 Git 历史策略。所有集成串行。
3. 需要 rebase 或解决冲突时，由 supervisor 控制写入权；如需改实现，明确交还 worker，重新交付。未知变更或真实冲突先查明，不强制覆盖。
4. 版本改变后复核受影响差异及验证前提。通过Git或简短记录保留候选与最终版本映射，执行必要组合验证；未变部分沿用适用证据，不默认重新全量测试或为每个尝试复制整套包、补丁和日志。
5. 通过后保存实现证据和账本检查点。已合入但验证失败时保持 integrating/blocked，停止依赖任务，保留现场并决定修复或按已授权策略回退；不自动做破坏性重置。

只读任务没有代码合入步骤，记录审核接纳的报告及证据即可。需求全部通过后，按项目约定处理需求分支进入目标分支；未获必要授权时报告内部完成和待交付动作，不能声称目标分支已更新。

## 故障与资源释放

先诊断再重试，区分实现失败、证据缺失、环境错误和内容冲突。目标正常前移可以重新核对集成，但持续竞争时暂停并协调写入，不能无限忙循环。保留任务身份、既有成果和尝试记录。

成功或中断均核实 worker 已停止。只在成果已接纳、现场无待保存内容且符合项目清理约定时释放临时执行位置；中断成果默认保留。不要求保留等待中的 agent，也不要求实现目录池。

文件、副本或worktree清理失败时，按[公共协议的删除约束](../../dev-progress-shared/SKILL.md#删除与清理受阻)立即停止该项，保留路径与原因；不使用强制参数、提权、改权限、杀进程或替代工具绕过，不为完成收尾制造干净现场。

### Worktree 收尾习惯

- 一个worktree的候选成果已审核通过、接纳到目标分支、必要集成验证通过且账本已落盘后，supervisor在同一次收尾中按授权和工具正常清理；遇阻立即保留，不把清理成功当作功能完成门槛。
- 清理前再次核对 worker 已停止、已知改动和需要的忽略文件均已接纳或保存、无进程依赖该目录。优先使用宿主的可恢复归档/清理能力，然后确认它已不再是活动 worktree，并向用户报告结果。
- 若尚有未保存成果、未完成审核/验证、活动进程或不明现场，不清理；在账本记录保留原因、worktree 路径和恢复动作。不为制造可清理状态而删除或覆盖成果。
